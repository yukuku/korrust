# Next five bounded language features

Baseline: `0cf4e6302`. This is an execution plan, not a support claim. Selection follows the final November 2 correctness reports, remaining-capabilities report, and unchanged AndroidBible sources.

1. **Private nested classes.** Support ordinary and data classes with lexical visibility checks, Kotlin metadata and JVM nesting visibility. `BackForwardListController.DisplayEntry` is a production example. Private inner and value classes remain explicit boundaries unless independently validated.
2. **Ordinary file annotations.** Parse package-header annotations, resolve their names after imports, validate FILE targets, and preserve retention on emitted file facades. `@OptIn` in `UnsignedBinarySearchKtTest` and `SongDocumentSerializers` motivates the missing header context, but opt-in enforcement, `@JvmName` and multifile facades remain explicit boundaries; ordinary annotation support alone does not unblock those files.
3. **Anonymous interface objects.** Support a bounded single-interface object expression with ordinary override methods, fresh allocation and lexical captures. `DevotionDownloadBackend` supplies a production example. Class/multiple supertypes, generic forms and unsupported member or enclosing-receiver shapes must reject explicitly. Generated-class reflection, enclosing-method metadata and debugger equivalence require separate evidence and are outside the selected runtime/interface-consumer scope.
4. **Suspend members and interface dispatch.** Extend logical suspend signatures and physical continuation ABI to bounded member declarations, implementations and interface defaults. `AudioHttp` supplies abstract/default/override examples. Immediate results and tail forwarding require real delayed-resumption validation; more complex state machines remain bounded by tested support.
5. **Primary constructor JVM overloads.** Support resolved `@JvmOverloads` on bounded ordinary primary constructors, reusing default-argument delegation. Production examples include `EmptyableRecyclerView` and `ColorPreference`. Test interleaved required/default parameters, evaluation order, descriptor collisions and Java consumers. Unsupported constructor contexts remain explicit boundaries.

Each feature requires review, appropriate Rust tests, formatting and Clippy, matching pinned-official differential inputs, and Java callers compiled against official output and executed against both providers with JVM verification where ABI changes apply. Include independent behavior assertions and invalid/unsupported boundaries. Freeze final compiler and fixture inputs before the final evidence run, retain hashes and command logs, derive counts from cases, and regenerate readable HTML reports. Additional app blockers are reported honestly; diagnostic advancement, emission, runtime behavior and full-app compatibility are distinct outcomes.

Implementation occurs in isolated copies. Delivery order follows acceptance readiness; the numbering above is selection order.
